# Chrona CI/CD

Chrona's workflow surface is intentionally reduced to five files.

| Workflow | Trigger | Main responsibility |
| --- | --- | --- |
| `update-commit.yml` | main push / weekly / manual | repository health and main-branch update checks |
| `debug-build.yml` | main push / manual | Debug unit/lint + four-ABI compile |
| `release-build.yml` | manual | signed release build, provenance and optional publication |
| `sync-source.yml` | weekly / manual | localization/source/dependency synchronization |
| `pull-request-issue.yml` | PR / issue / manual | review validation, dependency checks, CodeQL and issue intake |

## Debug build matrix

The Debug workflow compiles four ABIs:

```text
arm64-v8a
armeabi-v7a
x86
x86_64
```

Each matrix leg passes `-PchronaTargetAbi=<abi>` to Gradle, which maps the property to the Android NDK `abiFilters` setting.

### Artifact rule

A normal push builds the Debug APK but does not upload it. Artifact upload is available only for an explicit `workflow_dispatch` with `upload_artifact=true`.

No flashable ZIP artifact is generated by this workflow.

## Release build

Release packaging is manual-only.

Required inputs:

- release tag,
- pre-release flag,
- publication flag.

Signing material is restored in the GitHub `release` Environment and removed after the build job completes. Provenance attestation is handled by a separate least-privileged job. GitHub Release publication is optional and requires the explicit `publish=true` input.

## Update commit

The Update Commit workflow contains repository-wide health jobs for:

- source/header checks,
- Material 3 source audit,
- workflow contract audit,
- dependency graph inspection,
- CodeQL Kotlin/C++,
- OpenSSF Scorecard,
- Telegram renderer tests,
- commit summary.

It does not publish APKs.

## Source synchronization

The Sync Source workflow owns maintenance that changes repository source/resources, including Crowdin synchronization and dependency graph checks. Any created localization PR remains reviewable like normal source changes.

## Pull request / issue checks

Pull requests receive:

- repository audit,
- Material 3-only source audit,
- unit tests,
- lint,
- dependency review,
- CodeQL.

Issue events run a small intake validation that ensures a usable title/body exists without granting write permissions to the issue runner.

## Telegram

Telegram is an integration inside the five core workflows, not another workflow family. Notifications use separate secrets/chats for update/CI, pull requests/Dependabot, and releases.

## Build variants

Chrona has one `distribution` flavor dimension. `oss` is credential-free and uses a no-op
telemetry implementation; `play` keeps the production application ID and enables Firebase
Crashlytics/NDK only when a real `app/google-services.json` is supplied. Debug variants add
`.debug`. Release variants require the configured signing environment.
