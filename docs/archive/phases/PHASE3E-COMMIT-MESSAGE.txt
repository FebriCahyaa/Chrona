feat(phase3): add state-driven spatial motion for timer and stopwatch

Problem:
- Timer content changed between editor and countdown states without a unified motion contract.
- Stopwatch running and paused states lacked explicit spatial choreography.
- Lifecycle-to-motion mapping was implicit inside individual screens.

Changes:
- Add ChronaTimeToolMotionState as a pure visual lifecycle model.
- Add Timer and Stopwatch state-surface motion keys.
- Animate Timer idle, running, paused, and completed transitions with shared motion tokens.
- Animate Stopwatch idle, running, and paused transitions with the same spatial choreography.
- Add unit tests for timer and stopwatch lifecycle mapping.

Behavior:
- Timer editor and countdown surfaces morph instead of switching abruptly.
- Timer completion receives a distinct completed visual state.
- Stopwatch keeps its central time surface spatially stable while state changes animate.
- Existing ChronaTimeEngine, persistence, scheduler, and routes remain unchanged.
