feat(phase3): promote alarm and timer editors to spatial motion surfaces

Problem:
- Alarm creation used a blocking AlertDialog rather than an expressive editor surface.
- Existing Alarm cards had no explicit edit entry point for the full editor experience.
- Timer editor/countdown content lacked a dedicated motion identity for future spatial choreography.

Changes:
- Add ALARM_EDITOR and TIMER_EDITOR motion keys.
- Replace the Alarm add dialog with a unified Material 3 ModalBottomSheet editor.
- Add Edit action to expanded alarm cards.
- Preserve ringtone, repeat, label, vibration, enabled state and persistence callbacks.
- Apply TIMER_EDITOR to timer duration/countdown content.
- Add Phase 3D documentation and manifest.

Behavior:
- Tapping Add opens the Alarm editor sheet.
- Expanded alarms expose Edit, which opens the same editor with current values.
- Saving existing alarms calls onUpdate; creating alarms calls onAdd.
- Timer continues to use the existing ChronaTimeEngine-backed state and dashboard route.

Validation:
- Static source audit performed while packaging.
- No files deleted.
- Full Gradle build remains pending in CI.

Files:
- ChronaMotionKeys.kt
- AlarmScreen.kt
- TimerScreen.kt
- Phase 3D documentation/manifest files

Risks:
- End-to-end shared-element choreography between Dashboard and the editor sheet remains intentionally deferred until the navigation layer exposes editor-specific destination state.
