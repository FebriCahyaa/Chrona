feat(phase5): harden unified chrona time engine

Problem:
- Foreground time surfaces created independent timing loops.
- Timer and Stopwatch ViewModels mixed platform time reads with engine state.
- The shared engine refreshed active state around a one-second boundary.

Changes:
- Add an injectable ChronaWallClock and shared wallClockMillis StateFlow.
- Expose current epoch and monotonic reads through the shared ChronaTimeEngine.
- Replace one-second engine/UI timing loops with 50/100/250ms cadence based on active workload.
- Provide the application-scoped engine to the Compose tree through LocalChronaTimeEngine.
- Migrate ClockDisplay, AnalogClock, World Clock, Dashboard, Settings preview, Timer, and Stopwatch to the shared timing source.
- Add focused engine tests and JVM smoke verification.

Behavior:
- Stopwatch elapsed time remains based on SystemClock.elapsedRealtime().
- Timer foreground state remains monotonic while durable AlarmManager scheduling remains epoch-based.
- Clock UI surfaces share one app-scoped wall-clock stream and no longer own polling loops.

Validation:
- Engine JVM smoke test passed.
- delay(1000) audit passed.
- Direct Timer/Stopwatch platform-clock access audit passed.
- Source diff whitespace validation passed.
- Full Gradle test remains blocked by Gradle distribution network resolution in the current environment.
